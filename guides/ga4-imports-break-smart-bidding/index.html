Why GA4 Imports Can Break Smart Bidding

Lewis Phillips · 27 May 2026 · Updated 21 Nov 2026 · 11 min read

Smart Bidding can use conversions from GA4 or a native Google Ads tag. Problems arise when the campaign counts the same purchase twice, bids towards engagement events you only wanted to report on, or relies on an action that poorly measures the outcome you want.

Quick answer

Use one bidding action per outcome. A native Google Ads purchase or lead tag is usually the better Primary action because it records the event directly in Google Ads’ measurement path. If a GA4 import tracks the same outcome, set it to Secondary action for reporting and keep it out of custom goals used for bidding.

What Smart Bidding actually trains on

Smart Bidding (Target CPA, Target ROAS, Maximise Conversions, Maximise Conversion Value) learns by identifying patterns in the auction signals that preceded conversions. It needs conversions to learn from. The accuracy of those conversions as a signal is the most important variable in whether the algorithm performs.

Under Action optimisation, Primary actions count in Conversions and guide bidding when the campaign uses their standard goal through account-default or campaign-specific settings. Secondary actions normally appear in All conversions. A campaign using a custom goal bids towards every action in that goal, including Secondary actions.

Linking GA4 to Google Ads and choosing which events to use as conversion actions are separate steps. Actions created through the Analytics interface start as Secondary. Check or change their Action optimisation setting in Google Ads.

When can a GA4 import be Primary?

A GA4 import can be Primary if it reliably measures the outcome the campaign should drive. If you switch to a native tag or an offline conversion import for the same outcome, confirm the replacement records correctly before moving the GA4 import to Secondary.

Native tags vs GA4 imports: what the difference actually is

Configure the native tag to fire when the purchase completes and send the transaction ID and order value with the event. Google Ads receives the conversion directly within its own measurement path and handles attribution to the earlier ad interaction separately.

A GA4 conversion reaches Google Ads after GA4 collects and processes the event. The native tag avoids GA4’s attribution step and processing delays.

Both Google Ads website conversions and GA4-based conversions can combine observed and modelled data. The totals can differ because the two sources collect and attribute events differently. Smart Bidding can use either source when the campaign bids towards that action.

GA4 is useful for full-funnel reporting, attribution comparison and building audiences. When both sources track the same purchase, use one for bidding so a single order counts once towards the campaign’s goals.

Three ways GA4 imports can distort Smart Bidding

Check what each action measures, whether it duplicates another action and whether the campaign uses it for bidding.

01

GA4 import set as Primary with no native tag

An action created through GA4 starts as Secondary. The configuration to check is where someone has made the import Primary and the campaign relies on it for purchase measurement.

Check that the import records completed orders and passes the correct values. Compare the underlying purchase events with shop records and account for differences in attribution and reporting dates when reviewing Google Ads totals.

If the campaign needs a more direct purchase measurement path, validate a native tag before switching the bidding goal.

02

Both GA4 import and native tag set as Primary (double counting)

A native Google Ads action and a GA4 import can both record the same purchase. If both are Primary and their standard goal is in use, the same purchase can count twice. A custom goal can also cause duplication if it includes both actions.

If both actions count the same purchase towards the campaign’s goals, reported conversions rise and reported CPA falls at the same spend. That can distort bidding.

Identifying this: compare the Conversions column in Google Ads against actual order volume in your ecommerce platform for the same date range. Some natural variance exists (cross-device journeys, different attribution windows), but in my experience, if Google Ads shows far more conversions than you have orders, it’s usually counting some of them twice. You can also check by looking at the Source column in your Conversions table: if you see both Google Analytics and Website for the same event category, both may be Primary.

03

Non-purchase events included as Primary conversions

The hardest to catch. A campaign can bid towards imported engagement events (view_item, add_to_cart, begin_checkout) alongside purchases. If it does, the Conversions column mixes purchases with earlier steps. Count-based bidding works towards conversion volume, while value-based bidding can distinguish between actions by the values they report.

If the campaign bids towards view_item as well as purchases, product views can dominate the reported conversion count. Segment the report by conversion action to see the actual mix.

Go to Goals → Conversions → Summary and check Action optimisation. Keep the actions that measure the outcomes the campaign is meant to drive. Set engagement actions you only want to report on to Secondary action and exclude them from custom goals used for bidding.

How to diagnose the problem in your account

The quickest way to identify which version you have is to audit the Conversions table directly. Navigate to Goals → Conversions → Summary. Check each action’s source and Action optimisation setting, then review which goals each campaign uses.

How to fix it

Keep a reliable bidding action in place while making changes. If you need a replacement action, validate it before switching. Enhanced Conversions can improve measurement coverage.

01

Set duplicate GA4 imports to Secondary

Open Goals → Conversions → Summary in Google Ads. Select the duplicate GA4 action, choose Edit settings and set Action optimisation to Secondary action. Remove it from any custom goal where it would duplicate the bidding action you are keeping.

Do the same for events you only want to report on (add_to_cart, view_item, begin_checkout, sign_up). They still record and appear in All conversions. Check custom goals too, since they can include Secondary actions in bidding.

Important: if the GA4 import is the campaign’s only bidding action and you plan to replace it, implement the native tag first (step 02) and confirm it records correctly. Switch the campaign to the replacement action and move the duplicate import to Secondary as part of the same change.

02

Implement a native Google Ads conversion tag via GTM

In Google Ads, open Goals → Conversions → Summary, select + Create conversion action, then choose Conversions on a website. Set the category to Purchase, enter a conversion name, and set the value to use a variable (dynamic conversion value). Note the Conversion ID and Conversion Label that are generated.

In GTM, create a new tag of type Google Ads Conversion Tracking. Enter the Conversion ID and Conversion Label from the step above. Set the Conversion Value to your transaction revenue data layer variable (e.g. {{DLV - transaction_revenue}}). Map Transaction ID to your unique order ID variable. Set the tag to fire when the purchase completes.

Once published, the tag sends the transaction ID and value when the purchase completes. Google Ads handles attribution to the earlier ad interaction separately. Set Action optimisation to Primary action and include its standard goal in the campaigns that should bid towards purchases.

For lead generation accounts, the same principle applies: optimise toward the deepest reliable macro-conversion available. A native form-submission tag is usually the right starting point. If CRM data is available and GCLID matching is reliable, a clean offline qualified-lead import can be a stronger Primary signal than a form-submit alone, because it reflects lead quality, not just lead volume. If a GA4 form-submit action duplicates the lead outcome you use for bidding, keep it Secondary for reporting and exclude it from any custom bidding goal.

03

Enable Enhanced Conversions on the native tag

Enhanced Conversions supplements the native tag by sending a hashed first-party data signal (typically a hashed email address from the purchase confirmation page) alongside the conversion event. When Google can match that hash to a signed-in Google account, it can attribute conversions that would otherwise be missed due to cookie restrictions, ITP, or iOS privacy controls.

Go to Goals → Settings and turn on Enhanced conversions, then finish the setup in Google Tag Manager. Configure GTM to collect eligible customer data, such as the customer’s email address. GTM hashes the data using SHA-256 before sending it.

Enhanced Conversions supplements the native tag and can improve attribution where cookies are restricted.

What to expect after the fix

Smart Bidding retrains when the conversion signal changes. After setting the GA4 import to Secondary and establishing the native tag as Primary, expect a learning phase. During this period, Smart Bidding is re-calibrating to the new signal: bids may fluctuate and conversion volume may look different from the previous baseline.

The Conversions column will likely report fewer conversions than before if you have removed micro-conversions from the Primary set. That is the number correcting to reflect actual purchases rather than a mix of purchases and engagement events. The All Conversions column will continue to show the full picture.

Reported CPA or ROAS can shift when you change which actions count towards the campaign’s goals. Allow one to two conversion cycles for bidding to adjust and compare campaign reporting with actual orders or qualified leads before judging performance.

2026 Context

Consent Mode and the modelling gap

Where eligible, GA4 uses behavioural modelling to estimate otherwise unobservable user behaviour and key-event modelling to estimate attribution when it cannot observe the link directly. Google Ads can also model conversions to cover eligible gaps, including those related to consent or cross-device activity.

Consent affects what each source can observe directly and what it can model. For Google Ads bidding, the practical advantage of a native tag is that it records the event in Google Ads’ own measurement path and avoids GA4’s attribution and processing delays. Enhanced Conversions can improve measurement coverage where eligible first-party data is available.
