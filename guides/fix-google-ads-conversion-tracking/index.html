Google Ads Conversion Tracking Not Working? How to Fix It (2026)

By Lewis Phillips Published 21 May 2026 12 min read

Broken conversion tracking is not just a reporting problem. Smart Bidding uses your conversion data as its primary signal. If the data is wrong, your bids are wrong. This guide covers every common cause of conversion tracking failure, from basic installation issues to the architecture mistakes that silently degrade bidding performance, including 2026 Enhanced Conversions changes that affect how data reaches Google Ads.

Why It Matters

Why conversion tracking is the most important setting in your account

When Smart Bidding decides how much to bid for an auction, it draws on your historical conversion data. Every strategy (Target CPA, Target ROAS, Maximise Conversions) is working from that same signal. If the data feeding it is incomplete, duplicated, or miscategorised, the algorithm optimises toward the wrong thing. You can have excellent ad copy, tight keyword lists, and a competitive budget, and still get bad results because the conversion data is broken.

The problem is that most tracking failures are invisible. The account looks like it is working. Conversions are being recorded. But the signal going into Smart Bidding is off. Duplicate counting inflates reported performance, imported GA4 conversions compete with GTM-fired tags, or enhanced conversions are silently failing to pass user data. No warning fires. You just get worse bidding.

Fix conversion tracking first. Every other optimisation sits on top of it.

Fix Guide

How to fix Google Ads conversion tracking

Work through this sequence before investigating specific issues. Most problems surface at one of these seven checkpoints.

Before you start Do not make multiple tracking changes at once. Test one conversion action, one journey, one tag, one trigger at a time. Otherwise you will not know which change fixed the problem or broke something else.
  1. Check conversion action status In Google Ads: Goals > Conversions > Summary. Any action showing Inactive or Needs attention is a confirmed problem. Inactive means no signal received in the conversion window. Needs attention usually means an Enhanced Conversions error, a consent mode conflict, or a tag configuration issue.
  2. Verify the tag is firing Install Google Tag Assistant (free Chrome extension) and trigger a live test conversion by visiting the thank-you page, submitting the form, or completing the checkout. Tag Assistant shows which Google tags fired and whether data was sent to Google Ads. Check that the Conversion ID and Label in the tag match the values in your conversion action. Also confirm a Conversion Linker tag is present and firing on all pages. Without it, GCLID data does not carry across to the conversion page.
  3. Remove duplicate conversion counting Check whether both a GTM-deployed Google Ads Conversion Tag and a GA4-imported conversion action are set to Include in Conversions = On for the same event. That is double-counting. Set the GA4-imported action to secondary (Include in Conversions = Off). Only one primary source per conversion type.
  4. Confirm the trigger fires on the conversion event, not on page load In GTM, open the trigger attached to your conversion tag. If it is a Page View trigger on a thank-you URL, every visit to that page registers as a conversion, including direct navigation and refreshes. Use GTM Preview Mode to walk through the user journey and confirm the trigger fires only on the actual conversion.
  5. Enable Enhanced Conversions and verify data is passing In Goals > Conversions > Settings, enable Enhanced Conversions for web. In your GTM conversion tag, set user-provided data to Code mode and point it at a Data Layer Variable holding the user_data object (email and phone). Use the Enhanced Conversions Diagnostics in Google Ads to confirm user-provided data is being received and that match quality is healthy.
  6. Check Consent Mode v2 is not silently blocking conversions In GTM, check the consent settings on your Google Ads Conversion Tag. It should require ad_storage and ad_user_data. Confirm your Consent Mode default state tag fires before the consent banner, and that accepting the banner correctly updates the consent state to granted. Use Tag Assistant to verify consent state at each stage of the journey.
  7. Confirm auto-tagging is enabled In Google Ads: Admin > Account settings > Auto-tagging. Auto-tagging appends a GCLID parameter to landing page URLs that lets Google Ads connect ad clicks to conversions. Without it, attribution fails completely for click-based conversions.

Each issue below has a different root cause and a different fix. Identify which applies before making changes. Working through them randomly wastes time and makes it harder to know what actually resolved the problem.

1 Conversion action is inactive or shows "Needs attention"

This is usually the first warning you see. Inactive means the conversion tag has not fired within the conversion window (typically 30 days). Needs attention flags a configuration issue, often Enhanced Conversions failing or a consent mode conflict.

Fix

Run Tag Assistant on the conversion page to confirm whether the tag fires at all. If the tag fires but the status remains inactive, check that the Conversion ID and Label in the tag exactly match the values shown in your Google Ads conversion action. A single character difference causes a silent mismatch.

If Needs attention is caused by an Enhanced Conversions error, go to Goals > Conversions > Diagnostics. Google will flag the specific field causing the issue. Common causes: a phone number not in E.164 format (+44xxxxxxxxxx), or user_data being passed before the consent tag fires.

2 Duplicate conversion counting

This is the most widespread misconfiguration in Google Ads accounts. It happens when two sources are both tracking the same conversion and both are set as primary signals. The most common version: a GTM-deployed Google Ads Conversion Tag and a GA4-imported conversion action both set to Include in Conversions = On for the same event. Every conversion gets counted twice.

The impact goes beyond inflated reporting. Smart Bidding receives a corrupted signal. It thinks conversions are happening more frequently than they are, and at a lower CPA than is real. Campaign performance looks better than it is until you compare against actual revenue or CRM data.

Fix

Open every conversion action and identify any pairs tracking the same event from different sources. Set the GA4-imported version to secondary (Include in Conversions = Off). The GTM-deployed Google Ads Conversion Tag stays as the primary signal. Run this check every time you add a new conversion source.

3 GA4 conversions imported as primary

This is a subtle issue that most guides do not cover. Importing GA4 conversions into Google Ads is useful: it gives you GA4's attribution model as a reference point and makes cross-referencing easier. For most lead-generation accounts, though, I prefer a native Google Ads conversion tag as the primary bidding signal, with GA4 imports kept secondary for reporting and validation.

There are two reasons. First, GA4 uses session-based attribution by default, which attributes conversions differently to Google Ads click-based attribution. Bidding against that metric means Smart Bidding is working from data that does not match how Google Ads actually measures performance. Second, GA4 import latency means conversions can appear in reports with a delay, so the algorithm operates on incomplete recent data.

A GTM-deployed Google Ads Conversion Tag (GACT) fires directly into Google Ads with no intermediary and no attribution translation. That is the correct primary signal for most accounts.

Fix

In Google Ads: Goals > Conversions > Summary. For every conversion action imported from GA4, click into it and set Include in Conversions to Off. Keep the import for reference and reporting, but let your GTM-deployed GACT tags carry the bidding weight. The important rule is not to let two sources track the same event as primary conversions.

4 Conversion tag firing on page load instead of the actual conversion

This happens most often when an account is set up quickly. A conversion tag gets attached to a Page View trigger on the thank-you URL, which sounds correct, but Page View triggers fire on every visit to that page, not only on post-conversion visits. Direct navigation, link previews, and page refreshes all trigger it. Conversion rates of 20–40% in Search campaigns are usually the symptom.

Fix

In GTM, use a Form Submission trigger set to fire only on the specific form, or use a Custom Event trigger that fires on a dataLayer event pushed by your form confirmation logic. For Shopify checkouts (available on Grow plan and above), use the Customer Events system rather than GTM, as GTM cannot access the checkout pages.

Test in GTM Preview Mode: submit a test form and confirm the trigger fires exactly once, on submission, and not on the page load that follows.

5 Enhanced Conversions not enabled or misconfigured

Standard browser-side conversion tracking misses a growing share of conversions due to ad blockers, iOS Intelligent Tracking Prevention, and cookie consent restrictions. Enhanced Conversions recovers a portion of these by sending hashed customer data (email, phone) alongside the conversion signal, which Google uses to match to signed-in Google accounts.

The most common misconfiguration: the Google Ads Conversion Tag in GTM is set to use Automatic user data collection, which tries to scrape email addresses from the page DOM. This is unreliable. It misses users who type slowly, fails on single-page apps, and does not capture phone numbers. The correct approach is Code mode: push a structured user_data object to the dataLayer at the point of conversion, and point the tag at a Data Layer Variable that reads it.

Fix

Capture the email and phone from the form at submission time and push a structured user_data object to the dataLayer. Phone numbers must be in E.164 format (UK numbers starting with 07 become +447). In your GTM GACT tag, switch to Code mode and read the user_data via a Data Layer Variable. After 7 days, check the Enhanced Conversions Diagnostics in Google Ads to confirm user-provided data is being received and that match quality is healthy.

GTM dataLayer push: Enhanced Conversions (Code mode)
dataLayer.push({
  'event':     'conversion_form_submit',
  'user_data': {
    'email':        formEmail,        // raw — Google hashes it
    'phone_number': formPhone         // E.164: +447911123456
  }
});

6 Consent Mode v2 silently blocking conversions

This is the hardest issue to diagnose because there is no error. For advertisers targeting users in the EEA or UK, Consent Mode v2 is now a core part of Google Ads measurement. When correctly configured, it signals consent state to Google tags so they can behave appropriately for each user. When incorrectly configured, remarketing and attribution signals can be restricted, conversion modelling can be degraded, and data can be blocked silently for users who have not consented.

The failure mode: the Consent Mode default state tag is missing, fires too late, or sets the wrong consent types. Tags that require ad_storage fire before consent is granted on page load, then the consent signal never updates to granted even after the user accepts. Google tags interpret this as a permanently denied state and suppress the conversion.

Fix

Your Consent Mode default state tag must fire before any other Google tag on every page. Set it to fire on Consent Initialization, and set ad_storage and ad_user_data to denied by default. Your CMP (cookie banner) must push a consent update to the dataLayer when the user accepts. Verify in Tag Assistant that the consent state shows as granted for consenting users before the conversion tag fires. The GTM "2 tags not configured for consent" warning for Conversion Linker and CMP gallery templates is a false positive. These tag types do not expose the consent settings UI but respect consent natively.

7 Auto-tagging disabled

Without auto-tagging, Google Ads does not append a GCLID (Google Click ID) parameter to landing page URLs. GCLID is how Google Ads connects an ad click to a subsequent conversion. Disable it and click-based attribution stops working entirely. This is most often turned off accidentally after a URL rewrite or by a developer who thought the parameters were tracking spam.

Fix

Google Ads: Admin > Account settings > Auto-tagging. Toggle it on. If your website strips URL parameters (some CMSs do this), you may need to whitelist GCLID in your URL parameter handling, or use server-side auto-tagging instead.

2026 Update

2026 Enhanced Conversions changes to check

Google is consolidating how Enhanced Conversions works across web and leads. The key confirmed change: Enhanced Conversions for web and Enhanced Conversions for leads are being merged into a single on/off setting. At the same time, Google Ads now accepts user-provided data simultaneously from website tags, Data Manager, and API connections. Previously these operated more separately.

What this means in practice: if you have Enhanced Conversions enabled for web and are also sending data through Data Manager or an API integration, Google will now combine those signals. Check your Diagnostics report to confirm data is arriving correctly from each source and that match quality is healthy. If you set up Enhanced Conversions some time ago and have not reviewed the setup recently, now is a good time to re-test with Tag Assistant and check the Diagnostics panel for any flags.

The dataLayer structure used in the code example above (user_data with email and phone_number) aligns with Google's current documentation. If your implementation is older, cross-reference against the current field requirements in Google's Help Centre before assuming the existing setup is still correct.

FAQ

Common questions

Why is my Google Ads conversion tracking not working?

The most common reasons: the conversion tag is not installed or not firing on the right event, auto-tagging is disabled, duplicate conversion actions are both set as primary, Consent Mode v2 is blocking ad_storage for non-consenting users, or Enhanced Conversions is misconfigured. Start at Goals > Conversions > Summary and check status, then run Tag Assistant on the conversion page.

What does "Inactive" mean in Google Ads conversions?

Inactive means Google Ads has not received a signal from that conversion action within the conversion window (typically 30 days). The tag may not be installed, the trigger may not be firing, or the Conversion ID and Label in the tag may not match the action. It does not necessarily mean conversions are not happening. It means Google cannot see them.

Should I import GA4 conversions into Google Ads?

Yes, but in most lead-generation accounts, GA4-imported conversions work best as secondary (Include in Conversions = Off). Your primary Smart Bidding signal should be a GTM-deployed Google Ads Conversion Tag. GA4 imports are useful for cross-referencing and reporting, but the important rule is not to let two sources track the same event as primary conversions. Two primary signals for the same event confuse Smart Bidding and degrade performance.

How do I check if my Google Ads conversion tag is firing?

Install Google Tag Assistant (free Chrome extension) and navigate to or trigger the conversion event. Tag Assistant shows every Google tag that fires in real time. For GTM-deployed tags, use GTM Preview Mode to walk through the full user journey and confirm the trigger fires at the right point: on the actual conversion event, not on page load.

What is the difference between primary and secondary conversions in Google Ads?

Primary conversions (Include in Conversions = On) feed directly into Smart Bidding as the optimisation target. Secondary conversions are recorded in reports but do not influence bid decisions. Smart Bidding uses only primary conversions to decide how much to bid in each auction. If primary conversions are duplicated, miscategorised, or include low-quality signals, Smart Bidding optimises toward the wrong thing. Choose your primary actions carefully: they define what the algorithm is trying to achieve.
